## 1. Phase 2 Project Map & Live Verification Results

### 1.1 Architecture & Data Flow Map
- **Frontend (`frontend/src/`):** React 19.0.1 + Vite 6.2.3 + Tailwind CSS v4.1.14 Single-Page Application (`main.tsx` $\to$ `App.tsx`).
  - **Views (`frontend/src/components/`):** `Header.tsx` (navigation + demo state controller), `ChatView.tsx` (customer RAG chat + citation modal), `TicketFormView.tsx` (RFC validation + SLA preview), `AgentDashboardView.tsx` (ticket queue + AI Copilot draft editor), `KnowledgeManagerView.tsx` (multi-workspace persona config, document upload, 3-step AI verification studio), `Footer.tsx`.
  - **API Layer (`frontend/src/services/api.ts`):** Centralized `fetchWithTimeout` wrapper with `ApiError` handling and local fallback data (`frontend/src/data.ts`).
- **Backend (`backend/app/`):** Python FastAPI async ASGI server (`app/main.py` $\to$ `app/api/v1/api.py`).
  - **Routers (`backend/app/api/v1/endpoints/`):** `chat.py`, `tickets.py`, `agent.py`, `knowledge.py`, `workspaces.py`, `documents.py`, `health.py`.
  - **Services (`backend/app/services/`):** `rag_service.py`, `llm_service.py` (Gemini + Ollama), `embedding_service.py` (768-dim embeddings + pseudo-embedding fallback + Python cosine search), `fallback_service.py` (BM25 engine on `backend/data/seed_faq.json`), `ticket_service.py` (rule-based tags, SLA, LLM/template draft), `document_service.py` (`pypdf` + recursive splitter), `verification_service.py` (Synthetic QA $\to$ sandbox RAG $\to$ AI Judge).
  - **Database (`backend/app/db/session.py`, `backend/app/models/`):** SQLAlchemy 2.0 Async ORM (`Workspace`, `Document`, `KnowledgeChunk`, `FAQItem`, `Ticket`, `VerificationReport`, `VerificationItem`). Default local engine is `sqlite+aiosqlite:///.../backend/smartdesk.db`.

## 3. Additional Codebase Bugs & Weaknesses Found Beyond the Checklist

1. **Broken Citation Modal for Uploaded Workspace Documents (`knowledge.py#L60-L85` & `ChatView.tsx#L126-L140`):**

2. **Duplicate BM25 Citations in `rag_service.py#L63-L99`:**
   - In `RAGService.retrieve_context_documents()` (`backend/app/services/rag_service.py#L63-L99`), when `ws_id == 1` and `len(docs) < top_k`:
     - Lines `66-81` query `FAQItem` from the DB (`db_items`), **never use `db_items`**, and instead append `fallback_service.bm25.score(query)` results.
     - If `scored` had only 1 or 2 matches so `len(docs)` is still `< top_k`, lines `85-98` run `fallback_service.bm25.score(query)` **a second time** and append the exact same document(s) again without deduplicating by `doc_id`!
3. **Dead Configuration & Hardcoded Confidence in `rag_service.py`:**
   - `settings.RAG_CONFIDENCE_THRESHOLD` (`0.65` in `config.py#L40`) is never referenced anywhere in `backend/app/`.
   - `rag_service.py#L48` has the comment `# Filter out low-relevance chunks if score < 0.2`, but immediately appends every chunk regardless of score (`#L49`), even if cosine similarity is `0.001`.
   - `rag_service.py#L252` hardcodes `confidence=0.92` and `escalation_recommended=False` on every LLM response, regardless of retrieval similarity score or whether the LLM said "I don't know".
4. **Invalid Default Gemini Model Identifier (`config.py#L28` & `AGENTS.md` §1.1):**
   - `LLM_MODEL_NAME: str = "gemini-3.5-flash-lite"` is not a valid Google GenAI API model ID (live Google models are `gemini-2.5-flash-lite`, `gemini-2.5-flash`, `gemini-2.0-flash`). Calling Google's API with `models/gemini-3.5-flash-lite` triggers `404 NOT_FOUND` unless mapped/retried via a model alias fallback in `llm_service.py`.
